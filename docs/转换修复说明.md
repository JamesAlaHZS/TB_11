# CK 数据转换修复 v3

截图中的首张是 iOS 数据共享授权提示；实际异常为后续 ckData 赋值时无法把网页富文本转换为词典。它发生在请求腾讯云接口之前，不能据此判断 Cookie 已过期或推广地址有问题。

代码中可确认的薄弱点包括：部分分支把整份 COOKIE 而非当前循环账号传下去；HTML 直接插入 Cookie，特殊字符或包装后的数据会影响脚本；随后隐式把网页富文本当词典取 data.ck/data.url，缺少独立解析和结果校验。

本次处理：

- 单次任务统一使用当前账号；兼容纯文本 Cookie、Scriptable 的 cookie 包装、单账号词典与单元素数组，多个账号未选定时明确停止，避免选错账号。
- 配置和 Cookie 用无换行 Base64 传入本地 HTML，结果写入 DOM 文本，避免引号、反引号、百分号、HTML 或 URL 片段字符影响序列化。
- 网页结果先取纯文本，再显式解析成词典，校验成功后才读取 data.ck 和 data.url；缺 Token 或格式异常时显示无账号内容的中文提示。
- Scriptable 刷新 Cookie 时修正键名空格处理，保留值中的等号和填充符，正确更新 Token。

任务生成脚本、推广链接、腾讯云接口地址、任务等待及持久化存储增强功能保留。v3 时两个文件各 350 个动作；当前 folder-v4 各 354 个动作，继续保留本页全部修复，并补齐文件夹参数，详见[持久化目录修复](存储增强说明.md)。

验证：44 组虚构数据测试（含实际工作流 HTML 附件位置和模拟 Scriptable 请求）、动作 UUID/控制流检查、独立 Apple 证书链/签名/归档校验、签名前后全字段一致。没有读取或上传真实 Cookie 做测试。尚未在实际 iPhone/iPad 完成导入及任务验收，不能把代码测试等同为设备验证。

请重新导入仓库中名称统一为“-ala.shortcut”的最新版；这次修改了快捷指令本体，仅重新运行旧版或刷新远程配置不能修复。已有 ckfile.txt 无需删除。第一次运行仍可能出现 iOS 自身的数据权限确认，这与数据转换错误是两件事。
