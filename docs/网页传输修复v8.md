# ala-v8 网页传输修复
用户定位到 ckData ← data.ck 的富文本转词典错误。
已复现的原因：当前配置中保留的使用说明地址含 #readme，原版把整份配置拼入未编码的 data:text/html, 网址，# 变成网址片段分隔符。中国行重现时在HTML第613个字符处出现 #，后面的cookies赋值、run()和script结束标签不在网址正文中。此时不能取得预期的JSON结果。
当前配置中的链接没有删除或修改。修改的是8个data网址的传输：完整原始HTML → 原生无换行Base64编码 → data:text/html;charset=utf-8;base64, → 原来的网页读取动作。
所有网页脚本、Cookie刷新、结果取值、35次循环、打开淘宝、等待及返回快捷指令动作保持v7内容；除版本文字外，仅增加8个编码动作并修改对应8个网址参数。两份各302动作。
此前模拟直接执行HTML，未模拟它先被当成网址解析的步骤，因此漏检。新增检查同时重现旧地址截断、验证新地址无fragment且UTF-8内容逐字相同，并核对实际工作流8个编码引用链。新获取与已选择账号的模拟参数及任务URL检查通过。
config/和scripts/全部资源逐文件指纹保持一致，没有修改任何现有推广链接。真实账号内容未写入或上传。
两个文件重新签名，独立证书/归档校验及签名前后字段比对通过。未在实际iPhone运行，不以本地模拟代替真机验收。
