# 持久化状态判断修复 ala-v5

两个当前交付文件各 360 个动作，名称带 `-ala-v5.shortcut`；旧下载路径也更新至同一份内容。

用户在 iPhone 点“显示”确认，错误出现在“如果 ok 是”动作；运行通知为 v4 文案，因而不能归因于未导入 v4。目录准备与解析动作位于此判断之前，单独补文件夹参数不能解决这个判断错误。

v4 的两处状态判断直接把词典的 ok 字段作为文本条件输入，同时保留词典类型强制转换。当前版改为：明确获取词典值 → 文本动作生成独立字符串 → 按字符串比较。状态使用 ALA_STORE_OK / ALA_STORE_ERROR，避免 yes/no 风格值的自动类型歧义。持久化的添加、运行两条路径都使用同样修复；后续两处任务状态判断也先取文本。找到文件的标记初始化为非空 no。

相关输入形状参考[真实快捷指令参数与类型检查记录](https://github.com/viticci/shortcuts-playground-plugin/blob/main/codex/skills/shortcuts-playground/BEST_PRACTICES.md)。这些资料及本地结构测试不能替代实际 iOS 执行。

文件夹、ckfile.txt 的读取、校验、备份及账号合并流程保持 v4 内容。既有账号文件无需删除，推广链接、腾讯云依赖、任务生成脚本、等待流程均保留。没有上传真实 Cookie 做测试。

本地完成 54 项针对实际 v5 工作流的状态类型/内嵌 HTML 检查，另保留账号兼容与 Cookie 流程检查；签名与 Apple 证书链独立校验通过，签名前后工作流字段完全一致。检查重点加入词典类型输入不得直接用于字符串比较，避免只检查参数是否存在而遗漏类型。

导入名称带 ala-v5 的文件，并从带 v5 的新入口运行。持久化启动通知应包含“ala-v5”。不要删除旧账号文件。真机完整运行尚未验证。
