# CK 持久化目录参数修复 v4

本页记录 v4 的目录功能；当前为 ala-v5，每个文件 360 个动作，另见[持久化状态判断修复](持久化状态判断修复.md)。v5 保留本文的目录与账号保护流程。

## 本次故障与修复

“请为此操作中的每个参数选取值”出现在准备账号目录之后。检查交付文件发现，创建文件夹只有 WFFilePath，缺少必需的 WFFolder；文件已存在并不能补齐动作本身的参数。

本次为创建文件夹和保存文件明确设置内置 Shortcuts 容器，为按路径读取设置 WFFile。账号目录先取得 abc 文件夹，再以它的真实文件夹输出创建或取得 cookie 子目录，避免隐式输入和重复拼接路径。使用可移植的内置容器描述，不附带其他设备的书签或跨设备文件 ID。存储校验网页输出也先取文本再显式解析词典。

相关序列化字段可对照[公开导出的文件操作参数](https://github.com/hstagner/macos-shortcuts/blob/main/File%20Exist%20Kanban.shortcut)及[Shortcuts 动作参数记录](https://github.com/EachSheep/ShortcutsBench/blob/master/data/all_api2parasummary.json)。

## 账号保护

账号位置继续使用 iCloud Drive/Shortcuts/abc/cookie/ckfile.txt。目录不存在时自动准备；已有文件通过文本读取请求文件提供器取得内容，再进行格式校验。小云图标代表文件内容可能尚未下载，不代表目录不存在。

兼容空文件、UTF-8 BOM、标准账号 JSON、重复编码 JSON，以及可识别账号名的原始 Cookie/Stream 请求头。校验成功后，原内容备份至同目录 ckfile-backup.txt，再按原流程使用或合并账号。备份保存上一轮内容。无法安全识别时停止，不覆盖或自动删除原文件。

任务生成脚本、等待流程、推广链接、腾讯云依赖和原有用户主动选择的删除账号功能保持一致。此前 Cookie 输入与显式 JSON 解析修复继续保留。

## 验证与使用

完成 54 项针对实际导出动作及本地 HTML 的目录/存储检查、20 项账号兼容检查、44 项 Cookie 流程模拟检查；同时检查 UUID、控制流配对、非存储动作保持一致。两个最终文件均通过独立 Apple 证书链及签名校验，签名前后工作流字段完全一致。测试使用虚构账号。

重新导入两个同名文件以替换手机旧版即可，已有 ckfile.txt 无需删除，目录无需手工创建。本次修改的是快捷指令本体，刷新远程配置不能更新已安装的旧动作。未在真实 iPhone/iPad 执行；iOS 授权、iCloud 网络或文件提供器错误仍须以设备反馈为准，无法离线恢复云端尚未下载的账号。
