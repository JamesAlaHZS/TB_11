# CK 持久化存储增强

本文记录 storage-v2（335 动作）的存储功能；当前 cookie-v3 为 350 动作，并保留这些功能，另见[转换修复说明](转换修复说明.md)。

小云图标表示云盘中的项目尚未完全下载到本机，并不表示目录不存在。下载目录和删除旧文件是两个不同操作，因此不能仅凭随后运行成功判断唯一原因。

新版两个文件各 335 动作；原版为 277 动作。增加的动作仅用于持久化账号存储准备、读取与校验，任务、推广链接、腾讯云接口和原有显式“删除全部账号”功能保持原样。

自动处理流程：

1. 自动创建或取得 abc 和 abc/cookie 目录，目录已存在时沿用。
2. 列举目录寻找 ckfile.txt；文件不存在时按空账号库初始化，随后首次添加自动保存。
3. 已有文件通过文本读取请求文件提供器取得内容，不把仅存在云端的文件直接视为不存在。
4. 兼容空文件、UTF-8 BOM、标准账号 JSON、重复编码的 JSON，以及可识别账号名的原始 Cookie/Stream 请求头文本。
5. 校验成功后，把原内容备份为 abc/cookie/ckfile-backup.txt，再沿用原有账号合并保存流程；同名账号更新，其它账号保留。备份为上一轮内容，不是无限历史。
6. 内容确实无法安全解析时停止，原文件不覆盖、不自动删除。修正了首次保存成功提示引用另一分支输出的问题。

已检查：动作 UUID 唯一、控制流配对、原任务动作保持一致、20 项解析/账号保留检查、Apple 证书链及独立归档验签、签名前后全工作流字段完全一致。

边界：iOS 文件提供器的下载、授权与 iCloud 网络错误无法通过本地静态检查保证恢复。新版会自动读取以请求下载；目录缺失和普通首次初始化无需手工建目录或删文件。但云端内容无法取得时不能安全推断其为空，更不能承诺离线恢复尚未下载的旧账号。尚未在实际 iPhone/iPad 验证。

请导入两个名称带“存储增强”的新文件使用。原 ckfile.txt 和当前成功添加的账号无需删除。
