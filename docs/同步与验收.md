## 自动同步

上游实际地址是 GitCode 的 jiutiao/TTTASK，而不是一个可访问的同名 GitHub 仓库。maintenance/policy.json 记录 6 个确切源路径。GitHub Actions 每小时第 17 分检查，也可在 Actions → Sync ala resources → Run workflow 手动运行；GitHub 定时可能排队，不能保证整点执行。

处理顺序：下载全部资源 → 定向替换 → 解码扫描 → 检查 JSON 结构和全部 URL 字段 → 对比已审定的脚本 AST → 全部通过后统一提交。每次保存源内容和净化内容 SHA-256，可定位更新。快捷指令固定指向自己的 main 地址，配置更新通常无需重新下载快捷指令。

已知格式下的任务参数更新、原有推广短码变化可以同步。新增资源、URL 位置、未知编码链接、额外 POST 目标或脚本逻辑变更会使 Actions 失败，保留当前已发布版本。请在 GitHub 的 Watching/Actions 通知中关注失败。需要审查的新逻辑先在分支验证；审定后运行 `python maintenance/sync.py --initialize` 更新基线，检查差异再提交。不能对未知更新直接放行。

本地需要 Python 3 和 Node.js：

```sh
npm install --prefix maintenance --ignore-scripts
python maintenance/test_sync.py
python maintenance/sync.py
node maintenance/test.cjs
```

两份 -backup.json 与主配置内容一致，内部资源也均指向本仓库；原 CK 动作没有增加备用分支，因此 GitHub Raw 故障时不会凭空出现新的自动切换机制。GitHub 本身不可用时，需要等恢复或人工更换托管后重新签名。
